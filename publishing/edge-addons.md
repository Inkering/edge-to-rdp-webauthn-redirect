# Microsoft Edge Add-ons publication

This repository prepares an experimental extension for public distribution;
it does not claim store acceptance or production readiness.

Confirm these URLs are publicly accessible without sign-in before submission.
The privacy-policy URL assumes the published default branch is `main`.

Suggested single-purpose statement:

> Redirect WebAuthn requests from Microsoft Edge in a Linux xrdp desktop to
> the Windows RDP client's authenticator using a separately installed Linux
> native helper.

Suggested description:

> Use a Windows-connected FIDO2 security key, such as a YubiKey, for WebAuthn
> in Edge inside a Linux xrdp desktop. Requires the project's separate Linux
> helper and a Windows RDP client with WebAuthn redirection enabled. This
> experimental preview currently targets xrdp 0.9.24 and WebAuthn API 9.
> Channel-open reliability and some live lifecycle scenarios remain limited;
> read the setup instructions and known limitations before installing.
> This is not USB passthrough or Linux login integration.

Do not advertise general Chromium compatibility, every xrdp version, every
authenticator, or verified resident-passkey support. Do not imply endorsement
by Microsoft or Yubico.

## Permission justifications and data handling

| Permission | Required purpose |
| --- | --- |
| `webAuthenticationProxy` | Receive and complete browser-provided WebAuthn registration, authentication, and authenticator-capability requests for redirection. |
| `nativeMessaging` | Exchange those requests and responses with the explicitly authorized local host `org.local.xrdp_webauthn`. |

There are no host permissions, content scripts, or remotely downloaded
extension code. Authentication data are processed and transmitted through
the helper/RDP client even though no developer-operated collection service
exists. Store data-use declarations must reflect the actual flows documented
in `PRIVACY.md`; do not equate "no analytics" with "no user data processed."

## Package and submission

1. On the supported Linux setup, run the tests and real registration/
   authentication checks in the README. Validate fresh helper installation,
   missing-helper behavior, toolbar disconnect/reconnect, cancellation, and
   RDP disconnect handling. Resolve or accurately disclose remaining gaps.
2. Build with `python3 tools/package_extension.py`. Submit
   `build/edge-to-rdp-webauthn-redirect-0.1.1.zip`, not the repository or helper.
   The ZIP contains only `manifest.json`, `worker.js`, and four icons.
3. Capture real screenshots of the current UI without account names,
   credential identifiers, PINs, or other sensitive information. The committed
   logo is not a replacement for screenshots.
4. Register/use a Microsoft Edge developer account in Partner Center. Review
   the current store requirements, supply listing assets, permission
   explanations, data-use declarations, and the public privacy-policy URL.
5. Give reviewers explicit Linux/xrdp, Windows client, authenticator, and native
   helper setup instructions. Disclose that the extension cannot function
   without the separate helper and a supported RDP connection.
6. After a store ID is assigned, verify installation from that channel and
   register its exact ID with `install_native.py`. An unpacked extension ID
   is not a substitute. Retest the store build before announcing availability.

No signing key, CRX, extension ID, account credentials, or store submission is
generated by these tools. Preserve the store identity for subsequent releases
and increment the manifest version when publishing updates. The helper is
distributed separately from the extension-only package.
